## Security review

A read-only source-to-sink audit found no high-confidence exploitable finding in the current candidate.

Confirmed controls:

- Foreign runtime senders are rejected.
- Purple execution revalidates flow, capture provenance, exact origin, and current inspected page.
- Ephemeral Authorization values remain memory-only, are omitted from results/storage, and clear after completion or cancellation.
- Arazzo references resolve only against the loaded local OpenAPI baseline.
- MCP/A2A, HAR, and STIX-controlled strings render through text nodes rather than HTML sinks.
- Agent Inspector parsing is passive, bounded, moved to a dedicated worker, and terminated on cancellation.

Hardening gap, not a release-blocking vulnerability:

- Agent Inspector worker messages rely on the packaged worker and TypeScript contracts rather than runtime response-schema validation. A malformed internal worker response could cause an exception, but no attacker-controlled worker message path was found.

Unverified security/runtime areas:

- MV3 service-worker lifecycle during long Purple runs.
- Immediate IndexedDB interruption when a module worker is terminated across supported Chrome versions.
- Cookie and restricted-header behavior for isolated-world fetches.
- Runtime behavior at maximum retained HAR/IndexedDB history.
